============================================
Mark page content areas with TYPO3 13
============================================

Wrap the complete output of every page column with `f:mark.contentArea`. Pass the
numeric `colPos` configured in the backend layout.

The marker does not replace the existing renderer. It can wrap an `f:cObject`, a
loop over processed records, VHS output or Flux output.

..  _visual-editor-v13-cobject:

Wrap an f:cObject column renderer
=================================

..  code-block:: html
    :caption: Before

    <f:cObject
        typoscriptObjectPath="lib.dynamicContent"
        data="{colPos: 3}"
    />

..  code-block:: html
    :caption: After
    :emphasize-lines: 1,6

    <f:mark.contentArea colPos="3">
        <f:cObject
            typoscriptObjectPath="lib.dynamicContent"
            data="{colPos: 3}"
        />
    </f:mark.contentArea>

Replace `3` with the actual backend layout column number. The `colPos` passed to
the marker and to the existing renderer must describe the same column.

..  _visual-editor-v13-loop:

Wrap a processed-record loop
============================

Some projects fetch and render the column records before Fluid output. Wrap the
complete loop, not each individual record:

..  code-block:: html

    <f:mark.contentArea colPos="0">
        <f:for each="{children_0}" as="element">
            {element.renderedContent -> f:format.raw()}
        </f:for>
    </f:mark.contentArea>

The variable name is project-specific. Use the variable that already represents
all content elements from the selected column.

..  _visual-editor-v13-vhs:

Wrap VHS content rendering
==========================

..  code-block:: html
    :caption: Before

    <v:content.render column="0" />

..  code-block:: html
    :caption: After

    <f:mark.contentArea colPos="0">
        <v:content.render column="0" />
    </f:mark.contentArea>

..  _visual-editor-v13-flux:

Wrap Flux content rendering
===========================

Flux projects often derive a numeric column from the current record. Keep the
project's existing calculation and pass the same value to the marker:

..  code-block:: html
    :caption: Before

    <flux:content.render area="column0" />

..  code-block:: html
    :caption: After

    <f:mark.contentArea colPos="{data.uid}00">
        <flux:content.render area="column0" />
    </f:mark.contentArea>

The `{data.uid}00` convention is only an example used by existing Flux
integrations. Verify the actual numeric `colPos` generated by the project.

..  admonition:: Expected result

    The normal frontend output remains unchanged. In Visual Editor, every
    wrapped page column is represented by one drop zone with the correct column
    name and content restrictions.

..  _visual-editor-v13-test-page-dnd:

Test page-level drag and drop
=============================

#.  Place at least two content elements in the wrapped page column.
#.  Open the page in the :guilabel:`Editor` module.
#.  Drag the second element above the first one.
#.  Reload Visual Editor.
#.  Open the normal frontend.

When another page column has also been marked, move one element between the two
columns.

..  admonition:: Expected result

    Drag handles are visible and the changed order remains after reloading both
    Visual Editor and the normal frontend.

Continue with the optional :ref:`visual-editor-v13-container` or go directly to
:ref:`visual-editor-verify-result`.
